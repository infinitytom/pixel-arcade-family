# 更新游戏厅

此页对应 v1.6.3。首次安装请先看 [飞牛部署教程](fnos.md)。更新程序不用重新导入 ROM。

## 更新前保留什么

保留项目目录中的 `.env`、`roms/` 和 `cheats/`。如果 `ROM_DIR` 指向其他目录，也保留该目录。先在模拟器中导出重要存档；收藏、最近游玩、按键和每款游戏的画面设置保存在浏览器中。普通页面刷新不会删除它们，不要为了刷新界面清除网站数据。

保留旧版本程序文件和镜像，方便回退。不要把新版自带的空目录覆盖到已有游戏目录上。

## 用 Git 安装的 Docker 用户

在原项目目录执行：

```sh
git pull --ff-only
mkdir -p cheats
docker compose up -d --build
docker compose ps
docker compose logs --tail=80
```

如果 `git pull` 提示本地修改冲突，先备份本地修改并处理冲突，再继续；不要用强制重置覆盖自己的配置。镜像在本机从源码构建，单独执行 `docker compose pull` 不会构建此次界面更新。

## 下载 ZIP 的飞牛用户

1. 下载要更新的源码 ZIP，解压到临时目录。v1.2.0 使用 Release 中的 `pixel-arcade-family-v1.2.0.zip`；也可在仓库首页选择 Code → Download ZIP 获取 main。
2. 备份旧项目。将新版程序文件合并到原项目目录，包含 `Dockerfile`、`compose.yaml`、`site/`、`scripts/`、`server.py`、`catalog.py` 和 `engine-lock.json`；保留自己的 `.env`、`roms/`、`cheats/`。
3. 在项目根目录建立 `cheats` 文件夹。保留原 Compose 项目名与端口设置。
4. 飞牛 Docker → Compose → 原项目，重新构建并启动。也可在项目目录执行 `docker compose up -d --build`。
5. 等服务正常后，关闭原游戏页面，回到大厅用 `Ctrl+F5` 强制刷新。手机或电视浏览器重新加载页面；不要删除网站存储。

## 可选：安装原生金手指资源

滤镜、边框和遮罩随程序提供，不需要额外下载。金手指数据库从上游单独下载；未安装时，游戏仍可正常启动，金手指页会显示无可用项目。

在项目目录执行下面**一整行**命令。它使用容器中的 Python，不要求 NAS 另装 Python。`/roms` 是原有游戏目录的只读挂载，下载器只写入宿主机的 `cheats/`。

```sh
docker compose run --rm --no-deps --user 0 --entrypoint python -v ./cheats:/cheats arcade /app/scripts/fetch_cheats.py --destination /cheats --rom-root /roms
```

首次需能访问 GitHub 的 `raw.githubusercontent.com` 与 `codeload.github.com`。出现 `Installed: ...` 表示安装完成。刷新游戏页面后生效，不用再次构建镜像。新增游戏后可重新运行同一命令补齐对应资源；下载失败不会影响已有游戏，但应等完整安装成功后再刷新。

本地 Python 开发模式：

```sh
python scripts/fetch_cheats.py --rom-root /你的游戏目录
python server.py
```

Windows 可将 `python` 换成 `py -3`。默认下载位置为 `site/library/cheats/`；Docker 使用项目根目录的 `cheats/`，两种运行方式的资源目录不同。

数据库来源为 [FBNeo-cheats](https://github.com/finalburnneo/FBNeo-cheats) 和 [MAME 2003 Plus 的 cheat.dat](https://github.com/libretro/mame2003-plus-libretro/blob/master/metadata/cheat.dat)。下载器保留来源、SHA-256 和 MAME 原始署名；MAME 数据按 ROM 拆分以减少每次加载体积。上游未明确提供独立数据库的再分发许可，因此项目源码与 GitHub 发布包不打包这些数据库，由使用者按需下载到自己的部署中；本项目的 GPL 许可不覆盖它们。

## 更新后怎么用

- 游戏菜单 → **画面 · 滤镜与机台**：切换原始像素、像素平滑、老电视效果；选择木纹／奶白完整街机机台遮罩（灯箱、机框、摇杆按钮和投币面板）与额外屏幕纹理。关闭机台可恢复最大游戏画面。暂停侧栏可对比原画，像素平滑在继续游戏后呈现。设置按游戏路径和核心单独保存，可恢复默认。
- 游戏菜单 → **金手指**：FBNeo 显示原生可用选项，支持筛选、启用和关闭全部；MAME 2003 Plus 进入原生菜单的 `Cheat → Enable/Disable a Cheat`。MAME 菜单可用方向键与动作 A 进入；再次打开游戏厅菜单会关闭核心菜单。
- 金手指不会自动启用，FBA CPS1／CPS2 当前没有接入原生数据库。按 ROM 文件名精确匹配不等于 ROM 内容校验；修改版或改名 ROM 可能不兼容，不会自动套用父游戏代码。部分效果需重启游戏才能完全撤销。
- CRT 性能取决于游玩设备。觉得变慢或画面太暗时，切回原始像素并关闭遮罩。

## 如何回退

保留 `.env`、ROM、`cheats/` 和浏览器数据，恢复旧版程序和旧 `compose.yaml`，重新构建并启动。浏览器强制刷新即可。此次更新不迁移或修改 ROM，也不改动既有浏览器存档格式。

## v1.2.0 声音、存档缩略图与启动体验

本版同时更新 `catalog.py`、`server.py`、`compose.yaml` 和 `site/`。Docker 用户应按上文完整合并后重新构建，不要只覆盖几份 JavaScript。页面资源版本为 `arcade5`，新增 `sounds.js`、`presentation.js` 和 `game-layouts.json`。游戏画面比例资料已随程序提供，无需额外联网下载；核心、ROM 和金手指数据库仍按既有方式处理。

- 游戏厅设置 → 声音：开启／关闭、10%～100% 音量和试听；默认 20%。首次点击页面或键盘按键后浏览器允许发声。手柄移动限频，进入实际游戏画面后的动作不触发大厅音效；自动存档成功不发声。
- 新存档附带 256×192 的游戏画面缩略图，随所选时间更新；旧存档无图时显示占位，仍能正常载入。截图失败也不阻止保存进度。缩略图保存在当前浏览器的同一账号存档内，不上传 NAS。
- 启动前使用目录提供的比例或核心上次报告的实际比例摆放机台。内置资料包含 5,720 个 MAME 和 8,461 个 FBNeo 游戏的画面比例；未知改版首次运行前可能没有资料，实际比例将在核心报告后记住。自定义游戏可在 `gamelist.xml` 的对应 `<game>` 中填写 `<aspectratio>3/4</aspectratio>` 等比例。
- 海报向游戏画面过渡，加载完成后淡出；加载失败会退回重试入口。缺少海报时使用游戏厅图标。卡片选中反馈与短动画支持鼠标、键盘和手柄，遵循系统「减少动态效果」。

重要：浏览器数据绑定协议、域名和端口。沿用原访问地址才能继续使用原存档；普通更新与缓存维护不会删除存档。升级前旧快捷存档可先读取，再重新快捷存档加入历史列表。历史中没有保存过的画面无法补生成。
